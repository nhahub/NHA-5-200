# 1.3 Functional & Non-Functional Requirements
## UNSTUCK – Intelligent Freelance Intelligence Platform

---

## 1. Functional Requirements (FR)

Functional requirements define the core operational behaviors, features, and capabilities of the UNSTUCK platform.

| Req ID | Module / Area | Description | Priority |
| :--- | :--- | :--- | :--- |
| **FR-01** | Multi-Platform Scraping | The system must crawl project listings from 4 platforms: Mostaql, Khamsat, Nafezly, and Freelancer.com. | **Must Have** |
| **FR-02** | Automated Normalization | The crawler must normalize heterogeneous data formats (prices, durations, Arabic dates like "منذ ساعتين", skill tags) into a standardized `ProjectItem` schema. | **Must Have** |
| **FR-03** | PostgreSQL UPSERT | The system must execute `UPSERT` on the `projects` table using the unique project URL (`ON CONFLICT (url) DO UPDATE`) to prevent duplicate records and update existing entries. | **Must Have** |
| **FR-04** | Resilient Storage Fallback | In the event of PostgreSQL disconnection or downtime, the system must automatically fall back to reading from cached JSON files in `output/` without failing the user request. | **Must Have** |
| **FR-05** | User Registration & Validation | The system must validate user inputs (Full Name, Email, Password regex: min 10 chars, uppercase, lowercase, digit, special character). | **Must Have** |
| **FR-06** | Secure OTP Generation | The system must generate a 6-digit cryptographic OTP, store its SHA-256 hash, and enforce a 5-minute expiration period. | **Must Have** |
| **FR-07** | Real SMTP Delivery | The system must dispatch OTP emails using TLS SMTP without ever exposing the plain OTP code to the frontend client. | **Must Have** |
| **FR-08** | Anti-Brute-Force Safeguards | The verification system must limit OTP input attempts to a maximum of 5, after which the OTP is revoked. Resend OTP must enforce a 60-second cooldown timer. | **Must Have** |
| **FR-09** | Secure Authentication | The system must hash user passwords using salted bcrypt and refuse login to unverified user accounts. | **Must Have** |
| **FR-10** | Freelance DNA™ Profile | Users must be able to configure and store their skills, target budget, preferred platforms, and biographical overview. | **Must Have** |
| **FR-11** | Algorithmic Skill Matching | The system must calculate a match score (0–100%) between user skills and project requirements/content, categorizing matched vs. missing skills with written rationale. | **Must Have** |
| **FR-12** | AI Proposal Generation | The system must generate context-specific, professional proposals using LLM (GLM-4 Flash) with support for Arabic and English languages and custom tones (Value vs. Direct). | **Must Have** |
| **FR-13** | Offline Proposal Fallback | If the external AI LLM API is unreachable or times out, the system must seamlessly fall back to an internal intelligent template engine to ensure uninterrupted user service. | **Should Have** |
| **FR-14** | Opportunity Bookmarking | Users must be able to save opportunities to their "Saved Opportunities" list for later review. | **Should Have** |
| **FR-15** | Admin Scraper Hub | Administrators must have a dedicated interface to monitor database connection health, trigger individual or collective scrapers, and sync JSON files to PostgreSQL. | **Should Have** |
| **FR-16** | Market Pulse & Analytics | The system must display analytical metrics, platform distribution counts, and pricing indicators across scraped opportunities. | **Could Have** |

## 2. Non-Functional Requirements (NFR)

Non-functional requirements specify the architectural qualities, constraints, performance benchmarks, and security standards of the system.

### 2.1 Performance & Efficiency
- **NFR-01 (API Response Latency):** Read operations for `/api/projects` and `/api/status` must respond within **< 200 ms** when querying indexed PostgreSQL tables.
- **NFR-02 (AI Generation Throughput):** Proposal generation requests must return within **< 3.5 seconds** when calling the GLM-4 Flash LLM, and within **< 100 ms** under local template fallback.
- **NFR-03 (Scraper Throughput):** The Scrapy engine must crawl and parse at least 50 projects per minute per platform without triggering rate limits or bot blocks.

### 2.2 Security & Data Privacy
- **NFR-04 (Password Protection):** Passwords must never be stored in plain text. Salting and hashing must be performed using **bcrypt** with a minimum work factor of 12.
- **NFR-05 (Zero-Trust OTP Security):** Verification OTP codes must be hashed using **SHA-256** prior to storage. Plain OTP codes must never appear in API responses or frontend client payloads.
- **NFR-06 (Transport Layer Security):** All client-server and server-SMTP communication must utilize modern encryption protocols (TLS 1.2 / TLS 1.3).
- **NFR-07 (CORS Protection):** The API middleware must strictly regulate origins and method verbs to prevent cross-site request forgery.

### 2.3 Reliability & Fault Tolerance
- **NFR-08 (Dual-Layer Persistence Fallback):** The system must achieve **99.9% read availability** by automatically falling back to filesystem JSON storage whenever the primary PostgreSQL service is inaccessible.
- **NFR-09 (Database Fallback):** User authentication tables must feature an automatic **SQLite3 fallback** if PostgreSQL connection fails during cold startup.

### 2.4 Scalability & Maintainability
- **NFR-10 (Containerized Microservices):** Database, API, and automation workflows must run in isolated **Docker containers** managed via `docker-compose.yml`.
- **NFR-11 (Stateless Architecture):** The FastAPI backend must remain stateless to permit horizontal scaling behind a reverse proxy (e.g., Nginx).

### 2.5 Usability & Accessibility
- **NFR-12 (Responsive & Cross-Browser Design):** The UI must render seamlessly across modern desktop, tablet, and mobile browsers (Chrome, Edge, Firefox, Safari) with zero horizontal overflow.
- **NFR-13 (Bilingual UX & Typography):** The interface must fully support RTL (Right-to-Left) Arabic and LTR English typography with accessible contrast ratios conforming to **WCAG 2.1 AA** standards.
