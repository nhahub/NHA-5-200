# 2.2 Logical & Physical Schema Specification
## UNSTUCK – Intelligent Freelance Intelligence Platform

## 1. Physical Data Dictionary

### 1.1 Table: `users`
Stores user profile information, authentication credentials, and email verification status.

| Column Name | Physical Data Type | Constraints | Default | Description |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `SERIAL` | `PRIMARY KEY` | Auto-increment | Unique system identifier for each user. |
| `full_name` | `VARCHAR(150)` | `NOT NULL` | None | User's complete display name. |
| `email` | `VARCHAR(255)` | `UNIQUE, NOT NULL` | None | Unique email address used for login and notifications. |
| `password_hash` | `VARCHAR(255)` | `NOT NULL` | None | Salted bcrypt hash of user's password. |
| `is_verified` | `BOOLEAN` | `NOT NULL` | `FALSE` | Flag indicating successful 6-digit OTP email validation. |
| `created_at` | `TIMESTAMPTZ` | `NOT NULL` | `CURRENT_TIMESTAMP` | Timestamp of account registration. |
| `verified_at` | `TIMESTAMPTZ` | `NULLABLE` | `NULL` | Timestamp when the user verified their OTP code. |

**Indexes on `users`:**
- `idx_users_email` (B-Tree on `email`): Accelerates credential lookups during authentication.

---

### 1.2 Table: `otp_verifications`
Tracks one-time password generation, SHA-256 hash validation, attempt throttling, and expiration.

| Column Name | Physical Data Type | Constraints | Default | Description |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `SERIAL` | `PRIMARY KEY` | Auto-increment | Unique identifier for the OTP transaction. |
| `email` | `VARCHAR(255)` | `NOT NULL` | None | Target recipient email address. |
| `otp_hash` | `VARCHAR(255)` | `NOT NULL` | None | SHA-256 cryptographic digest of the 6-digit OTP code. |
| `attempts` | `INTEGER` | `NOT NULL` | `0` | Number of failed validation attempts (max 5). |
| `max_attempts` | `INTEGER` | `NOT NULL` | `5` | Maximum permissible failed attempts before invalidation. |
| `is_used` | `BOOLEAN` | `NOT NULL` | `FALSE` | Indicates single-use consumption of this OTP. |
| `expires_at` | `TIMESTAMPTZ` | `NOT NULL` | None | Strict expiration timestamp (5 minutes from creation). |
| `last_sent_at` | `TIMESTAMPTZ` | `NOT NULL` | `CURRENT_TIMESTAMP` | Enforces 60-second cooldown on resend requests. |
| `created_at` | `TIMESTAMPTZ` | `NOT NULL` | `CURRENT_TIMESTAMP` | Creation audit timestamp. |

**Indexes on `otp_verifications`:**
- `idx_otp_email` (B-Tree on `email`): Rapid retrieval of pending OTP tokens by user email.

### 1.3 Table: `projects`
Central repository for scraped freelance project opportunities across all integrated platforms.

| Column Name | Physical Data Type | Constraints | Default | Description |
| :--- | :--- | :--- | :--- | :--- |
| `id` | `SERIAL` | `PRIMARY KEY` | Auto-increment | Internal unique surrogate project ID. |
| `platform` | `VARCHAR(100)` | `NOT NULL` | None | Platform display name (Mostaql, Khamsat, Nafezly, Freelancer). |
| `platform_key` | `VARCHAR(50)` | `NOT NULL` | None | Normalized key identifier (`mostaql`, `khamsat`, etc.). |
| `title` | `TEXT` | `NOT NULL` | None | Full title of the freelance opportunity. |
| `url` | `TEXT` | `UNIQUE, NOT NULL` | None | Canonical project URL used as the PostgreSQL `UPSERT` key. |
| `price` | `VARCHAR(100)` | `NULLABLE` | None | Budget or price range offered by client. |
| `duration` | `VARCHAR(100)` | `NULLABLE` | None | Delivery duration expected by client. |
| `published_at` | `VARCHAR(100)` | `NULLABLE` | None | Relative or formatted posting time. |
| `brief` | `TEXT` | `NULLABLE` | None | Extended project description and client instructions. |
| `requirements` | `JSONB` | `NOT NULL` | `'[]'::jsonb` | Structured array of required skill tags. |
| `scraped_at` | `TIMESTAMPTZ` | `NOT NULL` | `CURRENT_TIMESTAMP` | Initial ingestion timestamp. |
| `updated_at` | `TIMESTAMPTZ` | `NOT NULL` | `CURRENT_TIMESTAMP` | Last updated timestamp via UPSERT. |

**Indexes on `projects`:**
- `idx_projects_url` (`UNIQUE B-Tree on url`): Enforces zero duplication and accelerates `ON CONFLICT` updates.
- `idx_projects_platform_key` (B-Tree on `platform_key`): Powers instant filtering by platform.
- `idx_projects_published_at` (B-Tree on `published_at DESC`): Optimizes timeline sorting.
- `idx_projects_requirements_gin` (`GIN on requirements`): Accelerates JSONB containment queries for skill matching.

## 2. Normalization & Optimization Analysis

### 2.1 First Normal Form (1NF) Compliance
- All attributes contain atomic values with no repeating groups.
- The `requirements` field utilizes PostgreSQL's native binary JSON format (`JSONB`), providing indexed set operations while allowing flexible schemas for varied multi-platform tags.

### 2.2 Second Normal Form (2NF) Compliance
- Every non-key attribute is fully functionally dependent on the entire primary key. In all entities, surrogate primary keys (`id`) eliminate partial dependencies.

### 2.3 Third Normal Form (3NF) & Boyce-Codd (BCNF) Compliance
- No transitive dependencies exist. Attributes depend exclusively on candidate keys.
- User authentication attributes (`password_hash`, `is_verified`) depend strictly on `email` and `id`.

### 2.4 Controlled Denormalization Rationale
- The `requirements` attribute is maintained as `JSONB` directly on `projects` rather than an isolated relational bridge table (`project_skills`). This design choice provides:
  1. **High scraping throughput:** Eliminates multi-table joins during massive batch inserts.
  2. **Direct JSON serializability:** Accelerates REST API responses directly into frontend client arrays without relational aggregation overhead.
